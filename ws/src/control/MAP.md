# MAP controller

Build with `cd ws && colcon build --packages-up-to control`, then `source install/setup.bash`. Generate the provisional table with `PYTHONPATH=ws/src/control python3 -m control.map_generate ws/src/control/config/map_model.json ws/src/control/config/autodrive_map_lut.npz`. Run `ros2 launch control race.launch.py track:=TRACK controller:=map speed_scale:=0.5`; `controller:=pure_pursuit` is the default. `ws/scripts/race.sh TRACK controller:=map` passes the same arguments. Record with `ros2 bag record /drive /odom /localized_pose`. Set ROS parameters through a custom launch file when tuning MAP.

MAP runs at 40 Hz. A map-frame pose supplies position and heading; `/odom` supplies forward speed. There is no independently measured lateral velocity, so heading approximates velocity direction in L1. The lookahead is `clip(0.4 * commanded_speed, 0.6, 3.0)` metres by default. The L1 acceleration is `2*v*v*sin(eta)/distance`. Measured speed is used for both L1 and lookup; below the table's 0.9 m/s minimum both use 0.9 m/s. This startup approximation is reported in diagnostics. The table uses the nearest speed column and sorted, valid acceleration samples; demanded acceleration is clamped to column support. Measured speed above 7 m/s stops the controller. Planned speed is capped at 7 m/s, and zero raceline speed remains zero. The AutoDRIVE bridge retains longitudinal acceleration limiting.

`config/vehicle.yaml` owns the 0.33 m wheelbase and 0.524 rad lock. `config/map_model.json` mirrors the planning parameters: mass 3.906 kg, rear axle to CG 0.155 m from the AutoDRIVE guide; front distance 0.175 m inferred from wheelbase; inertia 0.0492 kg m² estimated from f1tenth_gym; CG height 0.074 m from f1tenth_gym; tire B=10, C=1.6, E=0.5 and friction 0.7 are planning estimates. Pacejka D=1 multiplies the model friction. The [2026 simulator guide](https://autodrive-ecosystem.github.io/competitions/roboracer-sim-racing-guide-2026/#13-vehicle) instead describes a cubic-spline tire friction curve and lists a 0.324 m wheelbase. Its friction values do not identify Pacejka coefficients. See `docs/map_characterization.md` for simulator measurements. Regenerate the LUT after changing the model; mismatched metadata prevents activation.

The dynamics, fixed-steering simulations, 2 s duration, 0.01 s step, and last-versus-tenth-last yaw-rate convergence threshold of 0.05 follow [ETH-PBL MAP-Controller](https://github.com/ETH-PBL/MAP-Controller) revision `5cce3319a063e7a70c25de5d1bad3b9b8d278ee6`, described in the [paper](https://arxiv.org/html/2209.04346). RK4 replaces upstream `odeint`, and nonmonotonic tails are masked. The query corrects upstream reversed interpolation inputs. The [ForzaETH ROS 2 port](https://github.com/ForzaETH/race_stack/tree/ros2-humble/controller) informed the ROS interface; no empirical steering multiplier is used. See `MAP-LICENSE.md` for licensing.

Validate at low speed first, then complete laps using identical map, raceline, localization, and speed settings for pure pursuit and MAP. Compare bag-derived lap time, target versus measured speed, lateral tracking error, steering variation, collisions, and controller computation time. ROS and simulator validation require a sourced ROS 2 Humble environment and AutoDRIVE. The provisional model is not yet matched to the running simulator.
